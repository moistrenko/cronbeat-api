# Cronbeat — продуктовое описание

## Проблема

Задачи по расписанию (ночные бэкапы, рассылки, синхронизация с внешними API,
начисление подписок) ломаются молча. Успешное выполнение и полное отсутствие
выполнения выглядят снаружи одинаково — как тишина. Обычный мониторинг доступности
здесь не помогает: он стучится к сервису снаружи, а cron-задача живёт внутри сервера.

Про сломанный бэкап обычно узнают в тот единственный день, когда бэкап понадобился.

## Решение

Инверсия мониторинга — dead man's switch. Задача сама отчитывается о выполнении,
а сервис поднимает тревогу, когда отчёт не пришёл в срок.

1. Пользователь создаёт проверку и указывает ожидаемое расписание.
2. Сервис выдаёт уникальный URL для сигнала (пинга).
3. Пользователь дёргает этот URL в конце своей задачи.
4. Если сигнал не пришёл в срок с учётом допустимой задержки — приходит уведомление.

```bash
#!/bin/bash
pg_dump mydb > /backups/dump.sql && curl -fsS https://cronbeat.io/ping/a1b2c3d4
```

## Целевой пользователь

Разработчики и небольшие команды, у которых есть хотя бы один сервер с фоновыми
задачами: инди-разработчики, веб-студии, самозанятые devops-инженеры.
Аудитория целиком онлайн и достижима через Reddit, Hacker News, Habr, профильные
Telegram-каналы.

Первый пользователь продукта — автор проекта. Догфудинг обязателен: как только
появится прод, все свои задачи по расписанию переезжают на Cronbeat.

## Конкуренты

| Продукт | Позиционирование | Слабое место |
| --- | --- | --- |
| healthchecks.io | Open source, любим разработчиками | Устаревший интерфейс, слабый UX |
| Cronitor | Enterprise-мониторинг | Дорого, сложно для одного человека |
| Better Stack | Комплексный observability | Дорого, cron — второстепенная фича |
| Dead Man's Snitch | Минимализм | Мало интеграций, застывший продукт |

Свободная позиция: очень простой продукт с современным интерфейсом,
уведомлениями в Telegram из коробки и щедрым бесплатным тарифом.

## Границы MVP

Входит:

- регистрация и вход по email и паролю;
- создание проверки с простым интервалом («жду сигнал раз в N минут»);
- публичный эндпоинт приёма сигнала;
- фоновый процесс, замечающий опоздание;
- уведомление в Telegram.

Сознательно НЕ входит в MVP (появится позже по роадмапу):

- cron-выражения и таймзоны;
- команды, роли, приглашения;
- тарифы и приём платежей;
- графики и длинная история;
- публичные страницы статуса;
- мониторинг доступности сайтов и сроков сертификатов.

## Монетизация

Долгая игра. Порядок такой:

1. Бесплатный продукт + кнопка доната. Донат здесь не источник дохода,
   а индикатор: если люди донатят, продукт кому-то нужен.
2. Аудитория и обратная связь.
3. Платный тариф поверх бесплатного: расширенные лимиты проверок,
   длинная история, командная работа, приоритетные интеграции.

Ориентир по рынку: 5–50 долларов в месяц за подписку.

## Рынок и язык

Продукт англоязычный и глобальный с первого дня. Причины: поисковый спрос
на порядок больше, донаты через GitHub Sponsors и Ko-fi работают из коробки,
экосистема разработчиков говорит по-английски. Русскую локализацию можно
добавить позже.

Публичные тексты (README, интерфейс, лендинг) — на английском.
