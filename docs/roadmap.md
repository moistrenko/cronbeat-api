# Роадмап обучения и разработки

Спринт — примерно 1–2 недели при 10–15 часах в неделю. У каждого спринта одна
главная новая тема: спринты подобраны так, чтобы не изучать три сложные вещи
одновременно.

Порядок неслучаен. Прод появляется рано (спринт 5), потому что публичный URL
нужен для приёма сигналов, и с этого момента ты сам становишься пользователем
продукта — это лучший источник требований.

## Параллельные треки

Практика спринта — 7–10 часов. Сверху, не вместо:

| Спринт | Теория (fundamentals) | JS / TS / паттерны | Алгоритмы |
| --- | --- | --- | --- |
| 0 | Интернет: DNS, TCP, TLS | Замыкания и область видимости — только если останется время | O-нотация, 2 easy на массивы |
| 1 | HTTP, REST, SQL | Типы vs интерфейсы, union | Хэш-таблица, два указателя |
| 2 | Сессии, CORS, XSS, CSRF | Модули, `this`, прототипы | Строки, стек |
| 3 | Рендеринг, event loop, семантика | React-модель состояния vs Vue; композиция | Очередь, связный список |
| 4 | Идемпотентность HTTP | Discriminated unions для статусов | Бинарный поиск |
| 5 | Прокси, процессы, CI, TLS | Сборка, env, code splitting на пальцах | Повтор массивов / хешей |
| 6 | Время, таймзоны | Конечный автомат статуса проверки | Куча — идея приоритета |
| 7 | Очереди, ретраи, гонки | Наблюдатель, адаптер (каналы алертов) | BFS/DFS, одна задача |
| 8 | — | Стратегия расписаний на клиенте (cron vs interval) | Деревья: обход |
| 9 | Индексы, агрегаты | Виртуализация — теория списка | Ещё деревья / куча |
| 10 | Core Web Vitals, SEO | Бандл, LCP лендинга | 1 medium на выбор |

По итогам теоретического модуля — письменные ответы в `docs/interview/`.
Паттерн засчитывается, только когда он появился в PR и ты объяснил trade-off.
Алгоритмы: 1 medium или 2 easy в неделю на TypeScript, разбор рассуждения.

## Принципы, по которым мы работаем

**Одна новая сложность за раз.** Если спринт требует выучить и очереди, и
таймзоны — он разбивается на два.

**Вертикальный срез важнее слоя.** Лучше узкая фича, доведённая от базы данных
до кнопки в интерфейсе, чем «весь бэкенд, потом весь фронтенд».

**Сначала работает, потом красиво.** Рефакторинг — отдельная задача, и она
всегда стоит после того, как код заработал и покрылся тестами.

**Прод раньше, чем кажется нужным.** Задеплоенный кусок функциональности учит
большему, чем идеальный локальный прототип.
